# 执行进度卡（流内 TodoWrite 模式）

本技能通过 Markdown 三态清单与隐形 HTML 进度注释驱动客户端原生流内任务卡，**无需调用 `write_file` 创建任何 HTML 卡片或使用 `<agent-embed>`**。

## 推进格式

1. **开场建卡**：在首条进度汇报后，直接输出 3–6 项三态清单（第 1 项用 `[/]` 标记进行中，其余用 `[ ]`）：
   - `- [/] 第一阶段任务`
   - `- [ ] 第二阶段任务`
   - `- [ ] 第三阶段任务`
2. **阶段推进**：切换到第 `N` 阶段（`2..M`）时，在汇报文字末尾附加隐形注释 `<!-- todo:N/M -->`（阻塞时可附加 `<!-- todo:N/M blocked -->`）。不要在正文中重复打印清单或 `[N/M]` 文本。
3. **完成收尾**：全部阶段完成后，在最终回复的末尾附加 `<!-- todo:done -->`，流内任务卡会自动消失，保持对话整洁。

## 演示模式

当用户发送「演示执行进度卡」或调用 `/progress-card` 要求演示时，按以下三阶段执行：

1. 首句汇报并输出起始清单：
   - `- [/] 查看当前目录`
   - `- [ ] 执行等待验证`
   - `- [ ] 核对结果`
   然后查看当前目录内容。
2. 汇报发现并附上 `<!-- todo:2/3 -->`，执行无副作用的 `sleep 8`（`run_command` 等待阈值设为至少 `10000` 毫秒，保证同一次调用内完成）。
3. 汇报命令退出情况并附上 `<!-- todo:3/3 -->`，核对最终结果；全部核对无误后，在最终回复末尾附上 `<!-- todo:done -->` 完成演示。
